# 🚀 Release: `v0.2.0`

This release introduces **native integration with `pico-stack`**, enabling zero-configuration auto-discovery of `pico-pydantic` inside any Pico-based application.

There are **no behavioral changes** to validation, interceptors, decorators, or type handling.
The entire release is focused on **ecosystem consistency and improved developer experience**.

---

## ✨ What’s New

### 🔌 Pico-Stack Auto-Discovery

`pico-pydantic` now declares the standard:

```
pico_stack.modules
```

entry point.

This means:

* When using `pico-stack`, `pico-pydantic` is **loaded automatically** during container initialization.
* You **no longer need** to manually add `"pico_pydantic"` to your module list.
* Validation interceptors and `@validate` decorators become active as soon as the container boots.

**Before (manual):**

```python
container = init(
    modules=[
        "services",
        "pico_pydantic",
    ]
)
```

**Now (automatic):**

```python
from pico_stack import init

container = init(modules=["services"])
```

Everything works instantly — decorators, interceptors, hydration, validation — without explicit imports.

This aligns `pico-pydantic` with the rest of the ecosystem (`pico-fastapi`, `pico-celery`, etc.).
